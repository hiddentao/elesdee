Design notes
A Terminal-first

Dark and dense. The terminal is the centre, the chrome recedes, and status colour stays quiet.

The desktop view needs a wider screen. Switch to a laptop, or use Phone.

B Document-first

Warm paper and larger type. Replies read like a document, and the terminal sits in the page as a dark panel.

The desktop view needs a wider screen. Switch to a laptop, or use Phone.

Choices to review

  • Usage panel. A compact summary sits in the sidebar; click it for the full panel. Usage belongs to the computer, not to a session.
  • Phone navigation. There is no bottom bar. Usage opens from the top-right icon on the session list.
  • Phone keys. A key rail above the phone input sends desktop keys and combos to the session: Esc, Tab, arrows, Ctrl+C and latched modifiers. Hold to repeat. Custom keys open from the plus. Should the rail be on by default, or start hidden behind the keyboard button?
  • Permission card. The app card docks at the bottom of the session, while the agent's own prompt is still in the terminal. Does the card replace it, overlay it, or sit beside it?
  • Right dock. The dock shrinks the terminal instead of covering it. It is 360px in A and 380px in B.
  • Project tabs. Each project has its own tab strip. Switching projects replaces the strip; active sessions are always there, and a clicked session is added. The last active tab is restored. There is no tab minimize. Expanding a project does not collapse the others; the project whose tabs are shown is highlighted.
  • Collapsed projects. A collapsed project shows one blot per active session. Hover a blot for the tab name and whether it needs your attention.
  • First launch. The first screen checks the agents and adds a project. Is a name and folder enough, or should it also pair the phone?
  • New session. One form asks for the session type, project, name, starting provider with remaining usage, and source. A collapsed Additional settings section holds the first prompt, the copy choice and config overrides. The tab bar plus opens it; the project plus starts in that project. What else belongs in the form?
  • Repository. The source shows recent repositories. Searching all GitHub repositories needs a device-code connection; the token stays in the Keychain. Should the connection also live in Settings?
  • Providers. Add follows hezo's catalog: choose a provider, then sign in through its browser page, paste an API key, or enter a local server URL. Should provider setup be its own onboarding step?
  • Session usage. The bar sits in the provider pill and shows the current account's available usage. Hover for every limit and context left; click the pill to switch accounts.
  • Waiting states. Permissions, questions, idle input and new-session approvals share one card style. The sidebar marks the session Active; the session itself shows the waiting card.
  • Questions. The sidebar Questions chip lists every pending question across sessions. Answering one removes it; the agent can withdraw one it no longer needs. Should the list be a sidebar section instead of a popover?
  • Phone session list. The phone shows all sessions and groups the waiting ones. Should the phone hide closed sessions?

Sample data only. Terminal output, usage numbers, server addresses and screenshots are fixed. Actions change both directions and both devices at the same time, so the comparison stays fair.

Session states

    Colour is never the only cue. Active and Closed each have an icon and a status word. Waiting details appear on the session itself. The agent's terminal still shows the agent's own prompt; the app card is the shared approval surface.

    What the buttons do

    Title bar

    • New session opens the new session modal.
    • Language opens the 12-language list on first launch.

    Projects

    • Chevron and name select the project and collapse or expand it.
    • Plus starts a new session in that project.
    • Blot opens that active session; hover shows its tab name and whether it needs your attention.
    • Add project in the sidebar header, or on the first screen, opens the name and folder dialog.
    • Questions opens every pending question. The count drops when one is answered or withdrawn.
    • Settings in the sidebar footer opens a full-page view with General, Providers, Language, Devices and Diagnostics.

    Tabs

    • Project chip names the active project.
    • Tab activates that session in the project. Right-click for the session menu.
    • Plus sits after the last tab and opens the new session form.

    Session

    • Branch pill opens copy branch name, copy folder path, open folder and open in Terminal.
    • Provider pill switches provider or account. Its allowed pills toggle providers; the current one stays allowed.
    • Usage bar sits in the provider pill and shows the current account's available usage; hover for its limits and context left; the pill switches accounts.
    • Panel icon opens this session's right sidebar. Each session remembers its own panel.
    • Right-click a tab or a session row for rename, switch provider and close.

    Right dock

    • Files, Changes, Browser switch the panel for this session. The browser has its own tabs and logins.
    • Save saves the open file; Top up opens the provider top-up page.
    • Auto-switch turns automatic provider switching on or off.

    Phone

    • Usage (top right) opens every account and the session context.
    • Filters narrow to active or waiting sessions.
    • Overflow opens terminal and close actions.
    • Attach adds a file; Send sends the message.
